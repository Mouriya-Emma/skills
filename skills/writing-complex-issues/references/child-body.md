# child body 区块与 child 类型

什么时候读我：写 child body、选 child 类型、定 parent 归属时。

## 区块（按序）

**## 必须先读的关联 issue** — 回答「我继承了什么」。写：umbrella 编号 + 所继承契约条款的**逐字快照**；消费者写明所依赖契约的 owner child。自包含优先于 DRY：headless 读者不做跨 issue 图遍历。快照的是契约语义（状态空间、owner、不变量、错误分类）；owner child 合入后，签名与形状的权威在代码里，按 comment-layers 同步活跃快照，写 `owner/repo@<sha>` + 符号锚点，不抄一份会漂移的签名副本。

**## 目标** — 一句话，这个 child 解决的那一个问题。目标必须可追溯到方向原文、契约条款、或 repo 既有承诺（README / 设计文档 / 历史决策）。失败模式：**进口目标**——三处都追溯不到的目标（典型：给内网工具自带「应该有鉴权 / 加密 / 配额」）是作者价值观不是任务，不立 child；安全姿态、运维取舍属操作员独有事实，确会改变本树目标时按 decision-closure.md 在写作期直接问操作员。

**## 使用场景** — 回答「落地后用户/系统观察到什么使用形态」。业务层在 child 上的家。owner child 没有面向用户的完整功能时，写明经由哪条最薄真实入口能观察到它维护的状态语义，以及哪些消费者 child 在其上构建。与「预期结果」的分工：这里写场景叙事，那里写可验证性质。

**## 上下文** — 回答「已知事实钉在哪」。写：repo、design source、baseline 锚点——**概念锚点**（文件 + 符号 + 当前行为描述）并标注「实施前自行 grep 核对行号」。行号会漂而符号和行为不会；照搬旧行号的代价是 agent 在错误位置动手。repo 或指称尚未定位时在写作期定位（SKILL.md「开树前：解析操作员方向」），不编造路径，也不写「unknown」留给执行者——编造的锚点比缺失更糟，headless agent 会在虚构位置动手；缺失的锚点则把定位责任推给了执行者。

**## 问题** — 回答「现状为什么不满足目标」。写：可观察的症状 + 原因（哪个责任单元的哪项状态/规则、哪条不变量或能力缺口）+ 引用（代码锚点、历史决策原文、运行证据）；原因在写作期查证，规则同 `skill://writing-issue`「问题写到原因」。失败模式：在这里写改法——问题陈述被方案预设污染后，「预期结果」和「验收」全会被这个预设牵引；改法的位置在决策层（裁决后写入）或 PR。

**## 责任与必要决策** — 回答「本 child 在结构里担什么责任」。写：责任单元、核心或外围（见下文「实现 child 的责任」）、维护或消费的契约条款（快照在「必须先读」）、受影响的调用方、本单元内已裁决的目标级决策及依据。child 不自行裁决跨单元契约：继承树根裁决；写 child 时发现契约缺失或冲突，当场回到树根按 decision-closure 裁决并同步各快照，发布后才暴露的走设计修正。不写「待定」「未决项」。

**## 预期结果** — 回答「完成后观察到什么」。**用性质表述，不用机制枚举**，例如「agent 可达的一切 X 路径都经 Y 校验」；性质定义覆盖范围，不能仅凭措辞就认定旁路已被封住。配套写明实际保证机制、适用边界及真实路径验收。遵循全局 functional/ADT 偏好：语言与项目模型支持时优先用领域类型、受限构造和编译器穷尽检查；否则按项目惯例说明边界解析、运行时校验或协议约束如何保证性质。不把品牌类型或特定 union 写成通用硬要求，也不用 typecheck 替代 runtime 证据。

**## 不应残留** — 两半：本 child 范围内不许留下的（旧路径、兜底、字面量）；**本 issue 范围之外不应改动的**（防顺手越界）。消费者 child 另写：不在本地扩展、复制或重定义所消费的契约，不够用时走设计修正回到 owner。

**## 约束** — 只写外部强加的硬约束（继承自契约 + 本 child 独有）。失败模式：把偏好包装成约束——headless agent 无法区分「违反会坏」和「作者喜欢」，真约束被稀释。

**## 验收标准** — 使用 `skill://writing-issue` 的 checkpoint 契约（Dimension / Check / Command / Env / Expect）：每条预期结果都有真实路径直接观察它的覆盖行，Check 点名；卫生检查及实现者本次自写测试不能承担结果覆盖。模拟最省事路径，确认目标未达成时表不能全绿。维度覆盖实际的 function / environment / integration / assumption 风险；只能在实现后观察的已定方案结果，按 decision-closure 写成 owner child 经最薄真实入口的 assumption 行。

**## 继承验证义务**（如有）— 沿用 checkpoint 表，加 From / Original #，指明 owner；上游移交的义务不可二次延期。

**## 依赖关系** — Depends on / Blocks，写明需要上游的什么已交付后置条件；消费者点名它依赖的 owner child 及具体后置条件；不依赖某个 issue 将产出的事实或结论。语义上「无依赖」不等于可并行：物理共面（本 child 与哪些 siblings 改同一文件）由 umbrella「依赖图与编排」区块裁定，写「无」前先对照该区块。

## 实现 child 的责任：核心或外围

每个实现 child 在「责任与必要决策」标明责任属性，按它维护还是消费权威契约判定，不按工作名称（切分规则见 SKILL.md「切分轴」）：

- **核心（owner）**：维护或改变某项权威契约，或承载本次变更的中心逻辑。一个 owner child 管一项权威，或同一部件内不可分验收的一组；同一部件拥有互相独立的状态时拆开。它在同一 PR 交付契约的代码落地、真实行为和一条经真实入口的最薄路径，验收从该入口观察状态语义（合法转移、拒绝非法输入、生命周期结束）；不交付只有类型/接口的空基座。
- **外围（消费者）**：只消费已定契约——调用方迁移、不承担准入的入口面、文档对齐等。Depends on 所需的 owner 后置条件；验收它负责的入口面上的用户结果；同面 siblings 按编排串行，其余并行。

## child 类型（默认是实现 child，另有两种）

- **audit child（调查即 issue）**：只在两种形态下存在，都不承载未决项。**audit 充当树根**：自底向上开树时，写作期完成的**应然/实然/证据**登记表（每行：契约应然 + 现在的行为 + `file:line` 证据）装进 body，契约/设计落它的决策 comment，实现 children 从该 comment 的 §N 逐字快照继承（编号稳定性见 comment-layers）。**方向本身要求调查结论**：操作员要的交付物就是结论时，它是普通 issue，不 Blocks 本树任何实现；写作者不得为收口自己发现的缺口而开它——缺口在写作期查清。登记表不混方案——混入的代价是事实与判断失去分离，后续 child 引用事实时被迫连带继承未经裁决的方案；怎么改由各实现 child 承载。登记表条目编号一经引用即**稳定**：范围更正移出条目时保留编号并写明去向——重编号会让 children 对「条目#N」的引用静默断裂。
- **收尾 child**：Depends on 它收尾的全部 children，两种职责按需承担：**集成验收**——承担 umbrella「关闭验证」中没有自然承担者的功能端到端 checkpoint；**文档/登记对齐**——文档/登记/定性向修复后实态对齐，文档 drift 是一等偏离，计数类内容改为**从代码派生 + 测试守护**——手写计数必然再 drift。

## parent 归属

child 的 parent 由**问题的性质**决定，不由发现路径决定：契约债挂债务 umbrella，回归是独立 bug 不挂；审查中发现某 child 性质不符，移出树并留更正记录（移出 ≠ 删除，引用保持可解析）。

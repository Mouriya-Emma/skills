# umbrella body 区块

什么时候读我：开树、写 umbrella/RFC body 时。umbrella 装共享契约，自身不出 PR。每区块是一个必须回答的问题，写不出来说明调查还没到位；区块内容已由权威文档承载时，写必读章节而不复写（见 SKILL.md「权威文档只引用」），区块只补文档没有的新裁决与差异。区块按以下顺序排（reader 按这个顺序找东西），不适用的区块可省，保留的按序。失败模式：**umbrella 退化成分类索引**——只有背景 + 范围列表（按「严重度 / 主题」给 children 贴口味标签）而无契约、关闭验证、编排的 umbrella 没有承载任何 children 之外的信息；树根的全部价值在全局层，索引型 umbrella 等于树缺位。

**## 必须先读**（存在权威文档时）— 回答「哪些既有权威文档是本树的前提」。写：每条文档路径或链接 + 章节标题锚点 + 它决定本树的哪部分（结构模型、域归属、既有契约、约束）。只列章节，不摘抄正文。

**## 背景 / 为什么** — 回答「这棵树为什么存在、为什么是现在」。写：动机链，每句带引用（原始设计承诺、转折点决策的原文、量化的现状证据、操作员方向原文）。失败模式：无来源的转述——headless 读者无法核实，叙事漂移会放大成范围漂移；操作过程叙事（「我们做了什么」）——不承载目标信息，只挤占注意力；方向复读冒充动机——方向只给目标没给为什么时，复读它业务层仍是空的，按 SKILL.md「开树前：解析操作员方向」写作期查证或直接问操作员。

**## 系统定位（全局结构图）** — 回答「这个系统本质上是什么结构模型」。这是 children 一切架构切片的锚：**先在父层选定模型，子层的「系统定位」才有差别可言**——没有这个区块，每个 child 各自即兴选模型，切片之间不可比也拼不回全局。写三件事：

1. **结构模型选定**：状态机 / 流水线 / 分层 / 数据流 / 并发拓扑——常常不止一个，按部件各用各的，写明哪个部件用哪个模型、为什么这个模型符合系统本质。
2. **域清单**：每个域的值空间、owner 部件（创建并维护它的一方；外部系统拥有的写来源与本系统适配部件）、信任级、进入系统的准入边界（parse/校验点在哪）。
3. **全局守则**：跨域规则（如「每跨域恰一个 parse 点」「词表归谁类型归谁」「单一运行时来源对象」），children 的实现都要过这几条。

自底向上开树（发现集合先于树，见 SKILL.md 成树判据）时本区块**从发现归纳**：把 N 个发现按结构根因聚类——同一条边界、同一个部件、同一类失误模式（如「子进程调用无超时纪律」「先读后写无原子性」），每簇命名为一个错误类别并上升为全局守则，children 引用并各自过这几条。按严重度或主题口味分组（使用阻断 / 安全 / 健壮性）是索引不是结构——它不产出 children 必须共同遵守的任何东西。

失败模式：跳过此区块直接写契约——契约条款失去结构依托，children 的架构切片各说各话；模型选错比不选更糟，所以选定要给出「为什么是它」的论证，后续可经设计修正 comment 收回重选。

**## 契约** — 回答「所有 children 共同遵守什么」。建立在「系统定位」选定的模型之上。写：**权威契约清单**——本次新增或变更、被另一实现单元依赖的每项状态与规则，逐项写语义（状态空间、不变量、错误分类、接口语义）、owner 部件、落地它的 owner child、依赖它的 children；有生命周期的写开始与结束锚点及确认者，纯类型/接口不编造运行生命周期。沿用的既有契约已在权威文档里的，列必读章节，不重述；变更它的写差异，并由 owner child 同一 PR 更新该文档。另写行为规则、命名了的全局守则、**消灭伪二分的关键 reframe**（如「两种模式」重述为「同构执行 + 不同创建者」——reframe 砍掉的分叉比规则多）。children 引用并快照树内新裁决的条款，不重新定义。操作员给出的**交付约束**（截止期、预算）也是契约条款：相对日期转绝对（「90 天内」→ 具体日期），写明它改变哪些取舍（阶段顺序、调研深度上限）——截止期滞留在背景叙事的代价是 headless 执行者不读叙事做取舍，约束必须长在被 children 快照继承的条款上。两个方向的失败模式：跨单元契约留给 PR——每个 child 各自定义共享类型与状态，先合入者事实成为 owner；单元内部实现混进契约——children 失去设计自由度，契约审查退化成代码审查。想写一条实现结构时按 decision-closure 的 a/b 判据：会迫使另一实现单元同步改变的写成契约，只影响本单元内部的留给 PR。

**## 范围** — 回答「按实现结构拆成哪些 children」。写：每 bullet 对应一个 child，标明责任单元（系统定位模型里的部件、边界或入口面）、核心或外围、维护或消费哪些契约条款；一个 child 一个 closing PR，child 内仍需一段连贯 Why。切分规则见 SKILL.md「切分轴」：不按功能切，功能结果列在「关闭验证」。child 集合在写作期全部确定：决定责任单元的事实先查清；单元内的实例集合（如「每个域的迁移」）不拆成逐实例 child，也不等日后清点再开，而是由该单元的 child 以性质划定范围（「一切 X 都经 Y」），验收用真实查询证明全集覆盖。失败模式：按功能切——每个功能 child 各自重定义共享契约、同改核心文件；把实例集合硬写成假具体清单，或留一个「清点后再开 children」的占位——范围静默不完备或悬而未决。

**## 分阶段**（工作有阶段时）— 回答「为什么这个阶段存在」。**按契约可见性划分，不按工作量**：每阶段写明哪份契约在该阶段生效、什么「两套共存」边界适用。owner 先于消费者落地是依赖事实，由依赖图表达，本身不构成阶段；契约版本切换需要两套共存时才分阶段。按工作量切的失败模式：阶段边界落在契约中间，跨阶段的 children 不知道自己该遵守哪一版。

**## 不在范围内** — 回答「邻近但故意不做的是什么、归谁」。写：每项指明承载它的后续 issue/RFC。这个区块防 agent 顺手越界，与 child 的「不应残留」同等重要。

**## 关闭验证** — 回答「整棵树完成长什么样」。写：事实性终态条件表，每行可独立执行验证。每个用户可观察的功能结果占一行，写明承担其端到端 checkpoint 的 child：通常是补上该功能最后一块的外围 child；没有自然承担者时由集成收尾 child 承担（见 child-body）。owner child 经最薄入口的验收只证明它维护的状态语义，不代替这里的功能级行。umbrella 自身不出 PR，没有具名承担者的行等于没人验。失败模式：「tests pass」式条目——它无法区分「目标达成」与「测试没覆盖」，每行要能独立证伪。

**## 残留清单** — 回答「活跃路径里不许留下什么」。写：每条残留物 + owner child；**允许保留的例外也显式写**（什么、为什么是内禀的不算违例）。

**## 依赖图与编排** — 回答「什么能并行、什么必须串行」。图必须使用 mermaid。两种边，缺一不可：

1. **语义依赖**（Depends/Blocks）：谁需要谁的已交付行为。权威契约的消费者 Depends on 它实际需要的 owner child 后置条件；owner 先落地，由它按契约首定义共享结构。边只指向已交付行为的后置条件，不指向某个 issue 将产出的事实或结论。
2. **物理共面**：语义独立 ≠ 文件独立。盘点每个 child 触碰的文件 / 部件，被多个 children 反复改写的面是 contended surface——同面 children 串行成链并写明次序，后合入者 rebase 在已合入者之上，跨面才可并行。

失败模式：只画语义边——N 个 children 全写「依赖关系：无」却同改一个文件，一次性 fan 出去并行执行时互相 rebase、两个 agent 各自从零重写同一函数；把共享结构的定义权交给「谁先合入」——契约由合并顺序而非树根裁决决定。编排是依赖事实，不约束 child 的实现形态——它给实现者一个单 issue 内看不到的真相：哪个 owner 必须先落地、哪些 children 在改同一块面。

## retroactive umbrella / 层级模板

仅用于组织已落地工作，不把未来契约模板套在过去事实。标题以 `RFC:` 开头。段落按以下顺序，不适用的可省：

1. `## 背景 / 为什么`：带来源的中文散文；第一段含逐字英文串 **filed retroactively to umbrella work that already landed** 及实际时间窗口。
2. `## 范围`：每条说明已落地范围并附真实 issue/PR 链接，不用 checkbox。
3. `## 不在范围内`：仅写源明确排除的内容。
4. `## 设计决策 / approach`：可选，每项有当时来源，不补造方案。
5. `## 时间线`：实际落地窗口。
6. `## 实施 PR / 已挂 children`：已合并 PR、现有 child 与嵌套 sub-proposal 的链接列表。

不写未来时 `[ ]` Acceptance；用散文 How 与已落地 PR 说明实施。发布前剥掉起草 Source bundle。追溯组织放新 issue，不回写已落地 issue/PR body；图边按 mechanics 维护。需要对齐操作员写作风格时，先完整读取 1–2 份实际 umbrella，而不是以固定篇幅代替来源充分性。

# 状态追问、外部故障边界与性能优化

- **状态追问不等于重跑指令：** 用户询问进度、“其他问题呢”或质疑汇报时，先依据已有证据给出完整状态（已修、未修、范围外），不把状态询问当成扩大调查或重跑验证的授权。涉及子代理或后台任务时，它们自报的进度标签不是证据：回答前必须先按 `subagent-delegation` 规则读取执行记录，核实实际命令与结果（读取记录属于核查既有证据，不属于重跑验证），如实说明未核查部分；发现子代理或后台任务偏离任务时，先按同一规则终止它再汇报。
- **复用仍有效的验证：** 相关代码、配置与运行条件未变时，沿用已完成的验证证据；只在发生实质改动、出现新失败，或某条验收标准尚无证据时，才按既定验证职责运行覆盖真实 runtime 路径的检查。已完成的工作在没有新证据或新请求时不重开。
- **不可控外部与上游故障止损：** 区分本项目缺陷、预期行为、历史失败与不可控的外部/上游服务故障。外部或上游故障只排查到确认其故障边界及与当前任务的关系为止；不把修复无关或不可控的上游服务作为完成前提，如实记录原失败并完成所有可达工作。
- **性能优化同负载前后对比：** 性能优化先测出实际瓶颈再改动；使用同一负载对比改动前后的实测数值与取舍，并保持原有行为不变。

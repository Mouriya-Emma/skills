# 权威源头与生命周期

涉及任何状态时，先确定它的权威源头和生命周期，再决定读写与调用；不从手边已有的数据推断，也不为弥合推断与事实的差距增加机制。

- **权威：** 每项状态只有一个源头，即创建并维护它的一方。本系统只是自己所创建之物的源头；对其余状态只请求源头并等待结论，不越过源头管理其内部。
- **记录的性质：** 每条记录要么是本系统作为源头的事实，要么是从源头取回的副本（只代表取回那一刻），要么是索引或意图（指向对象、表达将做之事）。三者分开对待，索引与意图不当作状态使用。
- **同步等待：** 需要知道或改变非自有状态时，向源头请求并等待结论，再依结论记录；不先改自己的记录再去对齐，不以就近可得的数据代替源头。
- **生命周期：** 先找出有生命周期的对象，写清各自的开始与结束锚点及其确认者，判断是否嵌套。调用顺序由生命周期决定：内层在外层之内开始；结束外层前先结束其全部内层，最后写外层的结束锚点。
- **近处副本：** 以上成立之后，才可以为有实据的性能需要在源头之外增加更近的副本。像记忆化一样，每个副本都要单独斟酌并写清派生自哪个源头、依赖什么、何时失效、由谁如何刷新；它只加速读取，不成为新的源头。不因读取方便、响应观感或编码习惯而添加。
- **机制即信号：** 需要锁、标志位、仲裁、补偿或对账才能保持一致，说明权威、记录性质或生命周期划分有误；回到这三处修正，而不是增加机制。
